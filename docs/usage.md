# NEU-Dela 使用与开发指南

本文对应 **0.4.0**。[返回项目首页](../README.md) · [下载最新版](https://github.com/yzbcs/NEU-Dela/releases/latest)

## 安装与首次使用

在 [0.4.0 发布页](https://github.com/yzbcs/NEU-Dela/releases/tag/v0.4.0) 选择 Apple Silicon Mac 的 DMG 或 Windows x64 安装程序。Mac 将应用拖入“应用程序”后打开；Windows 按安装程序选择安装目录。

当前安装包未签名，系统可能提示无法验证发布者。Mac 包已完成桌面验证；Windows 包已生成并完成包内资源检查，尚未在 Windows 实机运行。遇到问题时，可在仓库 [Issues](https://github.com/yzbcs/NEU-Dela/issues) 提供系统版本、应用版本和复现步骤。

首次打开会进入“工作台首页”。课表、待办和笔记可直接使用，AI 与邮箱按需配置。应用加载失败时，启动页会显示原因并提供重试按钮。

## 首页与待办

“接下来”优先显示正在进行的课程，否则显示未来七天最近的课程或定时待办。点击即可打开对应记录。

未来七天安排按日期合并课程与待办，今天的课程会标注待上课、上课中或已结束。逾期待办和未设时间的待办单独显示；重复事项展示当前保存的下一次时间。

可以在首页新建、完成或恢复待办。“今日便利贴”提供完整管理，支持四色、定时提醒、每天/工作日/每周重复及推迟提醒。

- 勾选后立即保存完成状态，卡片暂留原位；再次点击可恢复。
- 点击“收起已完成”或离开页面后，列表会整理；普通完成项可在“已完成”中查看和恢复。
- 重复事项显示本次完成状态与下次时间；本次查看中撤销完成，可恢复原提醒时间。
- 点击待办通知会打开应用并定位到记录，便于继续编辑、推迟或完成。

提醒时间按北京时间处理。关闭窗口后应用保留托盘后台运行，**退出应用或电脑关机后不运行提醒**。在“今日便利贴”点击“测试提醒”，可检查通知权限和系统勿扰设置。

## 导入与使用课表

### 网页导入

1. 在“我的课表”点击“网页导入”，打开独立的研究生系统窗口。
2. 自行完成学校统一认证，进入个人课表并选择全学期。
3. 点击右上角“读取当前课表”。应用只读取当前展示的课程；分页列表应先选择显示全部。
4. 核对课程、星期、节次、周次、地点、学期与第一周周一，再保存。

导入窗口的登录状态与日常浏览器分开，无需把学校密码填入 NEU-Dela 设置。读取结果不会自动发送给 AI；后续开启工作台连接并向模型提问时，相关课程信息可能作为回答上下文发送给模型服务。

### PDF 与手动录入

可以导入本机课表 PDF，预览并修正后保存；扫描 PDF 和未识别的版式可手动录入。现有导入验证覆盖研究生网页与文本 PDF 样例，本科课表版式仍待补充。

课表支持单双周、自定义 12 节时间、按课程配色的周视图、时间冲突提示和 ICS 日历导出。相同课程在切周或切换主题后使用一致色系。请正确设置第一周周一，以便课程落在对应日期。

点击课程可核对时间与地点，也可新建本次课堂笔记：笔记填入课程信息，并归入以课程名称命名的笔记本。课程详情可打开同名分类的笔记与关联资料。

课表导入是读取与保存本机课程安排；当前没有接通成绩、考试、选课等其他个人教务数据。

## 笔记与关联资料

“资料与笔记 → 备忘录”采用笔记本、列表、正文三栏布局。支持新建或重命名笔记本、移动与置顶笔记、正文搜索、模板、格式工具栏、自动保存和导出。移除笔记本时，其中的笔记移入“未分类”。

清单在“阅读模式”下可点击圆圈完成或恢复。“问问 AI”会先保存笔记，再准备提问草稿；编辑并发送后才请求模型。

需要 AI 查阅本机资料时，请先在“资料与笔记”关联文件或文件夹。当前支持 PDF、Markdown、文本与代码文件的按需分段读取，以及按层查看文件夹。扫描 PDF、图片、Word 和网页正文尚未接入；关联链接不代表已抓取链接页面。

## 配置与使用 AI

### 连接模型服务

在“设置”中选择接口类型，填写服务地址与 API Key，点击“获取模型”，选择模型后保存。支持：

| 接口               | 用途                               |
| ------------------ | ---------------------------------- |
| OpenAI Responses   | 使用支持 Responses API 的服务      |
| Chat Completions   | 使用兼容 Chat Completions 的服务   |
| Anthropic Messages | 使用支持 Anthropic Messages 的服务 |

聊天底部可搜索及切换模型，每个会话独立保留模型选择。API Key 由使用者自行提供并在本机使用系统加密存储。工作台读取与保存需要所选模型及服务支持工具调用。

空白聊天提供“安排今天、整理课程笔记、查找学习资料”入口，点击后会准备可编辑的提问草稿并开启工作台连接，发送后才请求模型。

### 读取工作台

“工作台已连接”表示允许 AI 按问题读取课表、待办、笔记、已关联资料和已配置邮箱。相关内容会发送给当前选择的模型服务；关闭开关可进行普通聊天。

AI 可以按完成状态和北京时间日期筛选待办，按日期、周次与上课时间查询课程，搜索笔记并读取正文。发送工作台问题前会等待未完成的笔记保存。回复中的来源可以打开核对。

邮箱工具支持查询目录和读取邮件纯文本正文，**AI 不会发送邮件**。手动发信仍在邮箱界面完成。

### 创建记录与结果卡

可以明确要求：

- “帮我添加明天 20:00 的论文阅读提醒。”
- “把这些课程加入课表。”
- “把上面的内容保存成笔记。”

信息齐全的明确保存请求可以直接执行；缺少必要信息时先追问，普通建议不会自动保存。操作成功后，结果卡显示实际保存的记录，并提供查看、编辑与撤销入口。已在创建后编辑过的记录会保留，撤销不会直接删除它。

追加课程保留现有学期、节次、导入来源和原课程，跳过重复安排；如果出现重叠，结果卡标出冲突课程和周次。同一条回复中重复发出的等价创建请求复用已有结果。停止生成或模型续接失败时，已经成功保存的记录及结果卡仍会保留。

当前测试覆盖本地工具、实体保存、协议处理和结果卡交互，使用本机模拟模型。真实模型的自然语言理解与创建效果尚未验证；使用时可通过结果卡核对实际内容。

## 邮箱

支持学校云邮箱、QQ、163 和自定义 IMAP/SMTP，可配置多账号、查看文件夹、读信、下载附件、回复和发信。

邮箱通常需要客户端授权码。QQ 和 163 提供可编辑的主机预设；学校学生云邮箱请从网页邮箱设置确认 IMAP/SMTP 主机，不要直接套用教工邮箱参数。授权信息在本机使用系统加密存储。

## 搜索、外观与本机数据

侧栏“搜索工作台”或 `⌘/Ctrl + K` 可查询笔记正文、待办详情、课程信息、关联资料名称与路径、聊天记录。方向键选择结果，`Enter` 打开，`Escape` 关闭。搜索在本机执行，打开前会保存正在编辑的笔记；不会读取关联文件正文或下载邮件。

左下角“外观”支持浅色、深色与跟随系统，默认跟随系统；选择会在本机保存，重启后保留。界面动效跟随系统“减少动态效果”设置。

工作台数据和聊天记录保存在本机。“设置 → 帮助与诊断”提供日志及数据目录入口。AI 请求与邮箱功能分别连接使用者配置的外部服务，因此“本机保存”不等于所有功能都离线运行。

## 开发与验证

使用 Node.js 24.22.1（见 [.node-version](../.node-version)，项目要求 Node.js ≥ 24）。

```sh
npm ci
npm run dev
```

无需真实模型密钥的演示模式：

```sh
npm run demo
```

演示模式启动本机模拟 HTTP 服务和桌面窗口，使用人工测试密钥；演示数据位于 `assets/output/demo`，与普通启动的应用数据目录分开。

### 常用命令

| 命令                    | 作用                                                    |
| ----------------------- | ------------------------------------------------------- |
| `npm run typecheck`     | TypeScript 类型检查                                     |
| `npm run build`         | 类型检查与生产构建                                      |
| `npm test`              | 单元与本地 HTTP 协议测试                                |
| `npm run smoke:actions` | AI 创建、结果卡、启动与通知定位的桌面验证，包含重启恢复 |
| `npm run smoke:design`  | 首页、搜索、主题等界面验证                              |
| `npm run smoke`         | AI、工作台和邮件等完整桌面工作流验证                    |
| `npm run package:mac`   | 构建 Apple Silicon Mac DMG                              |
| `npm run package:win`   | 构建 Windows x64 NSIS 安装包                            |

桌面验证会启动真实 Electron 窗口；先构建再运行：

```sh
npm run build
npm test
npm run smoke:actions
```

可将最终 Mac 包的可执行文件传给动作验证：

```sh
npm run smoke:actions -- 'assets/output/releases/mac-arm64/NEU-Dela.app/Contents/MacOS/NEU-Dela'
```

动作验证报告与截图生成在 `assets/output/actions-validation`；完整桌面验证产物位于 `assets/output/ai-validation`。完整邮件模拟验证使用本机 IMAP 与 TLS SMTP，需要 OpenSSL 生成测试证书，不向外部收件人发信；普通安装使用不需要 OpenSSL。

### 代码位置

| 目录           | 内容                                        |
| -------------- | ------------------------------------------- |
| `src/main`     | Electron 主进程、模型服务、工作台存储与邮箱 |
| `src/renderer` | React 界面                                  |
| `src/shared`   | 共享类型、工作台模型与校验                  |
| `scripts`      | 开发演示、模拟服务与桌面验证入口            |
| `tests`        | 单元与协议测试                              |
| `assets`       | 图标、截图与本地生成产物                    |

打包产物默认位于 `assets/output/releases`。项目使用 Electron、React 和 TypeScript，依赖及脚本以 [package.json](../package.json) 为准。
